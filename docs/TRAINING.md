# 训练代码与发布范围

`scripts/train_compact_story_ppo.py` 是当前 SNN 整局教师辅助 PPO 入口，`--help` 列出参数。默认不执行训练，显式 `--execute` 才会启动。发布安装与冻结运行入口不会调用它。

本次优先发布可检查的源码、两组最终参数、配套配置与冻结结果，不把几十至数百 GB 的 rollout、教师状态库、优化器/中间 checkpoint 放入 Git。

- 可以用发布参数初始化新的训练，并配置自己的教师回放、采样预算和输出目录。
- 参数文件不是完整 Adam/原作进程快照；仅加载它不能声称无缝续接原来第 87/101 批优化器状态。
- 已通关参数经历过多阶段预训练、规则教师辅助和 PPO；本仓库不把一条缺少中间数据的命令包装成“从零必然复现通关”的流程。
- 历史 GRU、连续模型、离线蒸馏与探针保留在源代码中，其部分脚本依赖未发布的缓存。发布分支的默认推理入口不使用这些缓存。

## 主要设置应一起理解

原作保持同一局向后推进，采样和 PPO 更新是不同计数：采集的决策数可能大于进入该次优化的小批次行数；Adam 更新次数也不是原作游戏局数。`--steps`、`--workers`、`--ppo-sample-decisions`、`--micro-scenes`、`--epochs` 分别控制采样长度、实例数、优化样本选择、序列微批和学习遍数。

核心训练环节包括三价值头 PPO、候选移动指导、分时距风险目标、危急事件/教师档案回放以及脑内参数约束。规则教师的短期预测与更长路线监督存在适用边界，不能把可信度低的标签都当成绝对安全。

需要改变奖励、教师、位置指导或动作解码时，应记录配置并用冻结模型复测。训练中的滚动策略通关不能直接代表某个固定参数通关；训练使用随机采样，发布冻结评估使用 `family_mode`，二者行为分布也有区别。

## 已知的单轮采样问题

最新实验发现：每个实例 Game Over 后会自动重置，`--games-per-world 1` 不是可靠的“每实例只采一局并立即退役”机制。部分第二局数据进入了采样与 PPO。本次发布保留当时实现和问题记录，**没有把它标记为已修复**。

如果未来要实现严格单轮，必须让结束实例退役，并处理剩余实例与不满配额的序列尾部；不能只改停止阈值。现在请不要依赖该选项提供严格单局语义。最新实验的采样、奖励和指导修改还有明显退化，不能据此承诺继续增加训练量会变好。

通关基线代码与最新实验代码分支分开，后续训练成果建议使用新的结果目录、tag 和冻结报告，避免覆盖已通关参数。
