# 原作 NBNM 模型移植


## 原作移植的危险预测验收

每个原作都要实现从实时原作快照到逐候选危险场的完整链路。这是《永夜抄》和后续原作共同的验收项。以当前原作输入时钟为起点，对给定的移动、低速、射击和动作序列推演 4、12、24、48、96 个输入帧。

- 同一快照读取全部在场弹、出生动画、激光与敌机碰撞体。记录判定形状、开启与关闭的时钟、速度、加速、转向、原作 EX 指令和待执行队列。保留隐藏发射器与关卡调度线程。
- 读取原作正在执行的脚本位置、各线程计时、变量、栈、发射器参数和当前 RNG 状态。候选要按各自的自机位置和射击推进瞄准、击破及存活判定、原作回调、随机分支、新敌机与新弹出生。原作脚本和通用命令按版本登记，不能靠固定的符卡编号替代脚本执行。
- 逐帧合并当前及新增的全部碰撞体，按原作更新顺序求净距、可走区域和接续出口。未解析的命令、参数或回调要指出受影响的起始帧、对象和候选。未知部分不能产生「安全」标签。可以提前终止该候选的验证时域，继续保留已验证段。
- 用同一原作快照或匹配的实际输入前缀重跑不同候选。逐帧核对所有对象的出生、消失、形状、轨迹、判定开关和自机接触。验收覆盖六面、各原作关卡分支、激光回调、出生及复杂 EX 组合，也要验证自机瞄准、Boss 击破和随机分支会随输入变化。单个符卡或单个对象的位移复现只证明对应规则。
- 同一快照的通用演进只算一次，候选到原作读取不同输入或发生分支时再分开。记录实际决策耗时及预测覆盖。教师和网络共享格式一致的逐候选危险信息，冻结时仍由网络给所有移动动作评分。

《辉针城》已有实时 ECL 读取、候选发射推演、同输入原作复核及共享净距接口。移植要复用这条链的输入边界、候选分叉和验证方案，并按各原作版本实现脚本状态、随机数和物理规则适配。覆盖表以原作实测填报，单项几何补丁与全量验收分别记录。

### 《永夜抄》1.00d 原作对照

用 `audit_th08_ecl_catalog.py` 盘点原作加载的程序。该入口走 Lunatic 练习菜单，读完整子程序和时间线，按原作分支记录指令统计。原作读取范围已覆盖一至六面，包括四面 A/B 和 Final A/B。它用原作实际加载的数据确认规则清单。

用 `replay_th08_frozen_prefix.py --record-native-forecast` 从指定冻结局的相同落点执行候选输入。在私有原作进程逐帧记录全部占用弹槽和激光槽，并采集实际传给碰撞函数的判定范围。敌机检测和脚本直接调用的激光一并记录。输出 4、12、24、48、96 帧的已验证净距和是否接触。采样提前接触时，后续各时域可确认该路径有危险。退出后剩余物体演化仍无原作记录。

原作的候选分支是对照基准。安全区可查询连续坐标下的判定余量。压缩记录也在各时域末帧和实际停止帧输出间隔四像素的安全区网格，附原点、尺寸和按行打包的安全格。计算时使用该候选自己的判定范围和自机尺寸。若改变走位、射击或击破条件，需要使用对应分支的数据。第一面同落点左右候选在第 10 帧已发出不同的新弹。

四面 B 逐候选重走历史前缀约需 88 秒。现已接通从当前输入检查点直接推演的原作分支。在同一个隔离进程里保存游戏数据和动态对象，执行一个候选，再复原同一落点。原作 ECL、弹幕 EX、激光回调、射击与击破均走现有游戏代码。分支中新建的对象在复原时释放，分支要释放的既有对象保留到复原。碰撞和关卡状态变化可以提前结束分支。脚本和配置始终针对同版本原作，已知版式可参照 [TH08 1.00d 重建源码](https://github.com/N0zoM1z0/th08/tree/55e4aad7cb7d5707f40df86df97530ab5b3830a0)。

《永夜抄》新训、续训和冻结默认使用同一套原作分支预测。历史回放按报告记录的预测模式复现。每拍为 18 个起手动作各选一条候选路径，使用原作执行所得的净距和接触填入 407 维观测。几何搜索提出路径，路径和后续转向的安全信息来自原作分支结果。所选动作交给真正的游戏输入，随后比较这四帧的落点和碰撞。训练统计记录收到原作预测的采样行数，以及所选动作与原作一致的步数。五个时域分别记录覆盖，提前离开可玩场景的未观测时段保留未知。现阶段每个动作只验证一条候选路径。该路径有危险时，仍可能存在更安全的后续转向。

同一完整连接组策略接收 407 个感觉值，每四个原作帧从 18 个移动候选中选择最高分。持续射击由原作输入映射实现，任务禁止 Bomb 和续关。

训练时，48／96 帧中已实走确认的接触与无伤余量也用于训练走廊和风险读出。标签对应当时执行的候选命令序列。同一起手改变后续转向，需要使用新路线的预测。

配置 `forecast_native_narrow_exits` 后，48／96 帧预测在没有更宽路径时，会把原作已确认无接触且净距大于零的窄路提供给网络。输入保留实测净距，由网络对各动作评分。

## 原作适配流程

1. 从标题菜单进入实际 Lunatic Story。在隔离桌面控制原作，记录难度、机体、原生关卡和菜单状态。
2. 在输入检查点校准 18 个命令，覆盖高速、聚焦、斜移、场地边界和原作锁存的首帧。动作编号沿用共享策略的顺序。
3. 从原作读取弹幕的大小和运动、敌机身体、Boss、激光生命周期及道具。比较几何判定与原作碰撞。60 和 96 帧的检查各自保留样本和覆盖范围。
4. 按共享顺序填入 111 个移动与危险特征、18 个场景特征、144 个逐动作方向特征、8 个任务上下文特征和 126 个走廊特征。预测覆盖标志随原作能力填写。
5. 载入原脉冲模型的全部权重。几何预测随观察输入，神经读出给全部移动候选打分。原作接触、首次 Miss、Bomb 和续关立即使 NBNM 失败。阶段切换只由原作事件确认。
6. 保存权重路径、原作版本、观测协议、动作轨迹、分面与终局。相同原作落点的条件测试用于验证避弹，完整 Story 局用于统计通关率。

## 《辉针城》移植验收

冻结测使用 12 个未用于训练或选模的原作种子。2026 年 11 月 23 日确认的门槛是至少 7 局进入第四面、4 局进入第五面、3 局从开局 NBNM 通关。v9 实际成绩为 8 局进四面、6 局进五面、6 局进六面、5 局通关。保留逐种子首次碰撞和整局耗时，用于与第 109 批同种子比较。

`evaluate_nbnm_checkpoint.py` 读取配置中的 `qualification.stage_gate`。通过第四面须在原作连续 Story 中观察到第五面。局部练习和接管的前缀不计入该验收。

比较权重时，使用同一观测版本、JSON 配置和原作种子表。比较整套移植方案时，为各组保存实际使用的原作预测代码和配置。两种比较都沿用相同的原作难度、机体及自主选动作方式。分别保存两次输出目录。

```powershell
python scripts/evaluate_nbnm_checkpoint.py --config $heldOutSpec --checkpoint $cycle109 --task full_story --split test --output $baselineRun
python scripts/evaluate_nbnm_checkpoint.py --config $heldOutSpec --checkpoint $candidate --task full_story --split test --output $candidateRun
```

从各自的 `report.json` 读取 `full_story_qualification` 和 `episode_results`。按 `native_seed` 配对，核对 `stage_history`、`terminal_phase`、`stage_frame` 和 `full_game_NBNM`。同落点短测和教师轨迹使用开发种子，验收种子用于最终比较。

仅调整验收门槛时，可将新配置用于已有终局，单独保存新旧判定。

```powershell
python scripts/recheck_nbnm_qualification.py --report $nativeFrozenReport --config $acceptanceSpec --output $qualificationReport
```

使用 `compare_nbnm_frozen.py --task-group full_story --split test` 可在同一作业内逐次跑两组，输出逐种子对照和两组验收结果。此入口与单个冻结入口使用相同的 CUDA 作业锁。

正式冻结每次可操作移动都检查 18 个神经分数为有限值，并核对原作收到的是分数最高的动作。报告中的 `verified_movement_decisions` 记录通过检查的次数。外部修分、移动硬限制及缺失检查记录均无法通过移植验收。

调通长程激光时，分别与原作核对到第 60 和第 96 帧的发射、运动及碰撞判定，单独覆盖第 61 至 96 帧出生的激光。候选路线复核使用各自的自机位置、射击、敌机存活和随机数推进。原作脚本覆盖不足时，沿用已确认时段的证据。96 帧正式观测用 `native_emitter_forecast_frames: 96`。可在开发局比较 `corridor_risk.native_emission_recheck_limit` 为 0 或 4 时的真实接续及延迟，再选定整局配置。

## 跨原作的走廊搜索对照

两款原作都使用 4／12／24／48／72／96 的粗搜索节点。共用的部分是换向时点、候选保留和出口检查。各原作提供实际移动轨迹、预测净距、覆盖区间，以及射击和移动会改变的发弹行为。

按需细搜优先检查已有安全前段、后续接不上且预测覆盖可信的首动作。在受限区间内，以 4 帧为步长试少量换向点，保留已有粗搜路径，并复核新路径能否继续接出 12 或 24 帧。未搜到出口的方向保留未知。网络使用这些观察为全部 18 个动作打分。

在两款原作分别用同起点、同权重比较粗搜、按需细搜和逐 4 帧搜索。记录原作无伤接续、已证实的出口、首碰帧及决策耗时的中位数和 95 分位数。整局结果仍以网络自主冻结评估为准。

移植前在《辉针城》用同一套几何观察隔离评估额外 108 列接续输入。新增信息经过视觉输入映射进入全脑，在固定 997 拍原作观察上改变 495 拍的最高分动作。12 次监督更新后，四个实机窗口的无伤通过由 3 个降到 2 个。三条实机走过的局部接续仍把自机留在左墙。后续设计应分别验证前缀长度、真实离墙和离墙后的可接续区间，再使用跨多个候选的原作结果训练评分。首轮移植采用正式达标的 407 维权重。

只训练读出时，可在 `train_nbnm_verified_repair.py` 的 `--readout-only --reference-retention` 模式加上 `--precompute-reference-prefixes`。当原作观测和已执行动作逐步相同，多个复习窗口共用一次前缀回放。`reference-prefixes.json` 记录该次回放步数和耗时。

也可以在只训练读出时用 `--reuse-fixed-prefixes`，按原排程同时复用纠错与复习窗口的历史。每组历史首次使用时回放，`fixed-prefixes.json` 记录预计与实际重放步数。

原作冻结进行期间，可以用相同的短训参数加 `--prepare-fixed-prefixes`，提前前向重放这些历史。该入口与 `--execute` 互斥，提交的优化器更新为零。进度写入 `fixed-prefix-preparation.json`。随后用相同的短训参数加 `--execute`，可复用已落盘的完整脑状态。已有较大排程的状态时，可以加 `--reuse-prefix-archive` 指向其 `fixed-prefix-states.pt`。执行时核对源权重、环境、历史偏移和 CUDA 后端。所需窗口均匹配时直接复用，实际读取的路径记录在 `fixed-prefixes.json`。

`--reference-every-update` 需与 `--reference-retention` 一起使用。同一批原作参考窗口各使用两次，纠错样本和顺序保持一致。用独立候选和相同开发落点检验原有路线保持情况，再执行同种子整局冻结。

## 《永夜抄》首次冻结

当前配置支持经过校准的 1.00d 汉化原作。准备有原作资源的私有目录和项目使用的 d3d8to9 v1.16.0，将兼容的《辉针城》407 维策略与连接组配置交给启动器。

原作启动使用名为 `Touhou 08 App` 的 Windows 互斥锁。私有实例在对应启动调用处使用各自进程的锁名，保留原作 API 的真实返回值和结果判断。接入其他原作时，若要多实例采样，需要先在训练使用的原作入口实测多个实例同时开局。

```powershell
python scripts/evaluate_th08_nbnm.py `
  --spec $policySpec --checkpoint $frozenWeights `
  --executable $privateTh08Exe --d3d8to9 $d3d8to9Dll `
  --output $runDirectory --episodes 1
```

冻结与续训共用《永夜抄》的配置转换，保留已学习的读出头和权重，使用《永夜抄》的原作预测。每次开局从隔离工作目录的原作标题菜单开始。`episode-*/decisions.jsonl` 记录移动分数和实际命令，`progress.json` 提供进度，`report.json` 记录实测终局。使用 `--max-decisions` 产生有上限的诊断局。正式连打省略该选项。原作 RNG 目前由游戏初始化。

后续训练、冻结、教师采集和探针使用各自的 `th08.cfg` 关闭原作 BGM 和音效。录制启动时传入 `--record-audio` 恢复两者，录制标志写入评估报告。设置作用于本次原作私有副本。

对同一版本的两份冻结权重，可用 `--native-seed <0–65535>` 从相同的原作启动种子开始。接口在原作 Supervisor 写入初始种子的那一拍提供指定值，报告记录启动种子与游戏写入的各面 Replay 种子。种子只给游戏定初始状态，之后按原作推进。将两个局面的同种子实测通过后用于配对，常规自主连打使用任意自然起点。使用 `scripts/probe_th08_native_seed.py` 先作三次原作启动，比较同种子输入序列的逐次快照，并检查另一个种子在原作的记录。配对评估额外保存 `paired-entry.json`。按启动种子核对两局首个 407 维观察与实际入场状态，再比较首次接触和到达的关卡。 [原作初始化流程参考](https://raw.githubusercontent.com/GensokyoClub/th08/f345c7dee07b849f2ff93a0029ab5ede126bf12c/src/Supervisor.cpp#L511)

碰撞后的同落点验证用 `scripts/replay_th08_frozen_prefix.py --report ... --decision ... --output ...`。原作复走冻结局已记录的按键至指定动作前，逐拍核对关卡时钟、位置与符卡，并核对各面的原作种子。默认继续复走原失败路线。传入 `--corridor-move 0` 和 `--horizon 48` 可测试从动作 0 开始的预测走廊，或用 `--commands ...` 提供一组替换动作。比较报告中的 `branch_entry`、实际碰撞和 `verified_contiguous_frames`，用于筛选可进入教师的数据。新版同种子冻结在过面时对齐首个可操作帧。复走早期报告时可用 `--match-recorded-stage-entry`，每面以已记录的关卡时钟入场，并在报告里保留原作输入计数的偏移。`--refresh-corridor` 用每拍真实新场景重算替代路线。`--export-teacher` 只在替代命令连续实走且全段无接触时生成可用的监督档案。

静音训练、冻结评估和教师 Replay 采集可传入 `--unpaced`。它只在原作实际游玩时跳过等待下一帧的分支，菜单和过场继续使用原速。录制使用 `--record-audio`，按原速运行。使用一段对齐原作输入的四面 B Replay 对照，8192 帧每 128 帧取样，共 65 个快照，已采样的控制、物体和关卡状态一致。原作推进由 136.27 秒缩短至 5.45 秒。整局还包含感觉计算与全脑推理，耗时以实际冻结报告为准。

原作接触或资源违规终止时，`episode-*/first-contact-evidence.json` 保留碰撞前最多 96 个连续原作帧，包括 407 维观察、18 个动作的最终分数及其路线、短风险和走廊读出，以及 4／12／24 帧预测净距和 48／96 帧走廊证据。先核对接触是否发生在记录动作的四帧内，再读当拍的短程净距和覆盖标志。跨过场或原作缺测时段的接触单独记录为无法归到一拍。

同一面接触时额外记录按键前和接触读数处的近邻点弹、敌机和激光槽位。把位置、速度、EX 标志、碰撞尺寸和激活状态与该拍的预测对照，可以定位短程漏报来自何种原作对象。

新的接触记录还包含原作实际触发接触函数的调用位置。激光碰撞会带上判定时的中心、范围、旋转原点和角度，据此可区分弹幕池激光和敌机脚本回调产生的激光。

`nbnm.forecast_scripted_beams` 将三种已核对的敌机激光回调送入同一套净距几何。读取每拍实际传给原作碰撞函数的矩形和旋转参数。连续三帧的同一发射源支持短程运动外推，之后沿用预测末端的矩形。原作后续脚本改变与尚未执行的回调仍属于条件预测。可用 `scripts/evaluate_th08_nbnm.py --practice-stage 4` 从原作四面 B 练习入口复查。整面练习无伤通过写入 `stage_practice_NBNM`。

符卡诊断在原作已解锁的 `score.dat` 下用 `--practice-stage 4 --practice-spell 19`。第一个编号是原作四面 B 的入口，第二个是本面菜单槽。报告记录进入时的原作符卡 ID、难度及机体。实际出现过符卡后，活着走到原作结束标志才记入 `spell_practice_NBNM`，其中包含无伤超时。

启用 `nbnm.forecast_sweep_laser_births` 后，共享几何会用已匹配直线光束的同类发射器时钟排入新光束，再用原作激光生命周期产生 4／12／24／48／96 帧预测。该类发射器在原作首次生成激光的输入快照读数为 180。当前支持实测的垂直扫射家族，预测条件包括原作发射器持续存活与正常时间倍率。教师采集可用 `--forecast-sweep-laser-births` 同步设置。

开启 `nbnm.forecast_wide_beam_births` 时，四面 B Lunatic 符卡出现两组经核对的预演发射器后，以发射器轴向和脚本时钟预测宽光束首次碰撞。保持已验证的 15 帧起始矩形，实际回调出现后由实时读数接管。48 个原作 Replay 快照的起始预测与实际帧吻合，最长可提前 96 帧。整面实机首次碰撞确认属于原作符卡 92，触发时钟和尺寸与同类双束预演一致。教师可以用 `--forecast-wide-beam-births` 采同口径的 407 维观察。

同一原作符卡的环轨使魔会每 18 帧同步生成点弹。可用 `nbnm.forecast_orbital_point_births` 从当前原作使魔位置、脚本计时和最近四帧转角预测至多提前 12 帧的出生。出生首帧进入碰撞判定后，后续直行同样进入长程几何。以原作实际发射数据核对支持范围。教师使用 `--forecast-orbital-point-births` 保持观察一致。

录像教学窗口可用 `scripts/capture_th08_teacher_windows.py --forecast-scripted-beams --forecast-spawn-animations` 采用同样的观察配置。采集清单记录实际出现敌机激光的观察数，以及通过原作动作核对并进入教师监督的动作数。

Final B 实测符卡 166 的环形激光开始后，原作时钟 81 出现 128 个点弹动画，90 帧启用判定。`forecast_final_b_ring` 读取 52 条激光的环心和共享时钟，在动画出现前预报确定重合的判定区域。角相位由原作决定，预报将判定框按可能的旋转位移收缩。出现原作弹动画后转回直接读到的开始时刻。该信息进入已有的感觉输入，保持 407 维和现有策略权重。两种原作起手均记录到这个阶段间隔。

阶段结束后可用 `train_th08_nbnm.py --continue-from <latest-training.pt> --upgrade-original-geometry` 启用上述原作观察并保留同一参数组的 Adam 状态。设定新的累计预算和输出目录，续训从新的原作采样局开始。 可用 `--save-parameters-at <累计决策数>` 保留中途已完成更新批次的冻结权重。

依次保存《辉针城》的 `full_story_qualification.qualified` 报告、《永夜抄》加载原权重的冻结报告和续训后的冻结报告。冻结和训练命令共用 `FLY_TOUHOU_NBNM_PHASE_DB` 指定的本机作业数据库。

首次移植实测运行 1175 个策略决策，一面 Boss 符卡在累计第 4768 个原作输入帧接触。最后一拍可见对象产生的 4 帧几何净距为 −1.45 像素，全部动作都缺净空。向前一拍仍有 13 个短程候选和 6 个条件下直行 24 帧可行的方向。此类证据用于定位更早的选路分歧，未执行分支的实际结果由原作复走验证。

TH08 的四面 A/B、六面 A/B 保留原作编号。报告同时保存共同的六面序列、实际分支和 `verified_movement_decisions`。计入通关需要从一到六面依次推进、进入原作正常终局、零接触、零 Miss、零 Bomb 和零续关。中止的评估在进度文件中标为 `stopped`。

当前 TH08 预测使用已观察弹幕、敌机与激光的条件轨迹。新的发射、脚本突变和敌机附加身体仍有覆盖缺口。候选评分保持这一输入范围，实际碰撞以原作事件为准。

`nbnm.forecast_spawn_animations` 可在观察中加入已见但尚在生成动画中的点弹。先解析当前原作动画时钟和直线指令尾部。第一个可碰撞帧包含动画速度和激活后速度两次位移。对有后续 EX 的弹幕，只在可以确认的位置和时域提供提示。二面原作录像的 2322 个可匹配激活均复现了帧和位置，另有一个槽位无法匹配。对已识别的静止等待 EX，依据原作计时保留激活后最多 24 帧。二面原作录像复核了 38815 个位置，均与静止预测吻合。此配置用于与同权重的原始观察做冻结对照。

EX64 单独生效且后续指令等待时，出生动画释放后继续按原作内部计时减速、转向，直到当前指令最后一次转向。原作释放帧包含一次动画位移和一次活动位移。六面 B 关卡帧 3512 的记录中，31 颗点弹从出生动画跨入可碰撞状态，四帧位置的最大误差为 0.000035 像素。与旧感知的冻结对照各用固定版本。

`nbnm.corridor_risk.short_risk_priority` 可用于测试短风险与长走廊的冲突。以网络当前首选的 4 帧风险达到 0.20、另有方向低于或等于 0.10 为试验触发条件。触发时将所有候选的两项神经走廊分数统一缩为原来的四分之一。路线、短风险和全部 18 个移动选项仍由网络评分。分数是模型输出的风险值，阈值用于相对比较。报告保留条件及实机第一次接触。

当滚动搜索漏掉某个首动作的接续时，若已有的同动作持续执行轨迹在 48 或 96 帧内仍留有超过 1 像素的预测余量，就把这条可执行轨迹写入走廊观察。它沿用原预测的置信度，作为网络选择动作时的输入。复核时从同一 Lunatic 录像重新采集，并比较原作动作、281 维基础观察与两个时域的走廊见证。

## 《永夜抄》续训

首次冻结后，可从同一份 407 维全脑权重启动原作 Story PPO。每个实例使用独立的原作工作目录。采样按实例就绪顺序处理，以 256 个决策组成 PPO 批次。学习完成后，存活实例从实际游戏位置和携带的脑状态继续。

```powershell
python scripts/train_th08_nbnm.py `
  --spec $policySpec --checkpoint $frozenWeights `
  --executable $privateTh08Exe --d3d8to9 $d3d8to9Dll `
  --output $trainingDirectory --workers 4 --segment-decisions 2048 --decisions 8192 `
  --teacher-windows $teacherManifest --teacher-every 4
```

追加 `--execute` 启动，省略时只输出拟运行的配置。任务在第一次原作接触、Bomb、续关或终局时结束。三个价值通道使用 NBNM 成败、成功用时和原作过面事件。每次实际过面记六分之一进度。几何预测继续作为模型输入。风险监督使用实际执行的动作和原作确认的接触。走廊见证使用同一面内实际无伤推进 48／96 帧的片段。

首次跨游戏训练从共享权重和新的 Adam 状态开始。中断后用原参数追加 `--execute --resume`，读取最近一次提交的模型、Adam 和待更新样本。重启时游戏实例重新开局，运行中的各采样段之间保留现场。`progress.json` 分别显示已采样决策和已提交更新。`latest-parameters.pt` 可交给冻结入口复测。

需要追加已完成的预算时，使用新的输出目录并传入 `--continue-from $parentTrainingCheckpoint --execute`。检查点使用上一轮的 `latest-training.pt`。`--decisions` 填累计目标。例如从 8192 拍追加 4096 拍时填 12288。新作业保留模型、Adam、随机状态和教师轮换进度，并记录继承光标。可以在原教师清单之后追加已验证的清单，沿用原先的面别轮换、权重和频率。

可以复用同一个策略混合采样原作 Story 与已解锁的 Practice Start。追加 `--practice-stage 1 --practice-stage 4` 将最后两个实例分给二面、四面 B，其余实例从一面开局。参数使用原作从零开始的关卡编号。扩展已完成的作业时可以为新作业指定练习面。恢复同一作业时沿用原分配。练习实例从原作私有副本的 `score.dat` 读解锁进度，并使用原作设定的初始火力。只有原作整面完成后的结算转换记为练习通过，任务记在 `stage_practice_*`。六面 NBNM 由独立的 Story 冻结评估确认。

训练局发生可归到一次决策的接触时，将前后原作槽位和当拍动作写入 `native-contact-evidence.jsonl`，供对照学生的短风险、路线分数与预测净距。

为每款原作单独调整接口时，可从同一原始权重启动 `--train-scope encoder-heads`。这组只更新感觉端口映射、移动读出、短风险读出及启用的走廊读出。连接增益、神经元动力学参数、三个价值头和 Bomb 头均固定，仍通过完整脉冲脑进行前向和反传。该作业的优化器参数名单写入 `parameter-scope.json`。恢复同一作业需保留该参数，并用固定权重的独立 Story 评估确认迁移结果。

## 《永夜抄》教师窗口

原作 Replay 可从指定关卡采集 407 维观察和连续四帧动作。先读录像中的阶段编号和原生输入，再在同版原作中测量各帧位置。只有四帧持续射击、移动与原作位置逐帧一致的片段才进入动作监督。在输入不匹配处断开序列。6A、6B 使用各自的原作关卡编号 6、7。如果关卡计时在后段停止，可用 `--replay-input-offset` 直接选择录像文件的输入下标。采集器用原作实际键位匹配一段唯一的录像序列，再逐帧核对采集区间内的键位与位置。 [原作录像格式参考](https://github.com/GensokyoClub/th08/blob/f345c7dee07b849f2ff93a0029ab5ede126bf12c/src/ReplayManager.hpp)

```powershell
python scripts/capture_th08_teacher_windows.py `
  --replay $teacherReplay --raw-stage 0 --first-stage-frame 480 `
  --executable $privateTh08Exe --d3d8to9 $d3d8to9Dll `
  --output $teacherDirectory
```

原作达到危险前可运行 `scripts/capture_th08_exit_teacher.py`，从学生当局的位置采集撤离示范。当检测到经过核实的原作发射前兆，首选动作接不上走廊而其他候选仍有出口时，采集器沿可行走廊操作。每拍对照原作输入计数、人物落点和碰撞状态。通过 96 帧的片段进入监督数据，并保存前 16 决策供脑状态热身。道中已发出的弹幕也可用 `--include-ordinary-closures` 采集，`--first-stage-frame` 可把采集范围设在已观测到的失误之前。需要先跨过较早的危险时可加 `--assist-before-recording`。在到达采集范围前，只为原首选动作即将接触时寻找一个替代移动。实际保存按指定关卡和符卡范围。教师采集单独记账。

续训可传 `--teacher-native-exit-weight 0.2`，对实走成功且具备 48／96 帧后续测量的首步校准出口读出。实测撤离中的教师转向增加动作监督权重。有实测撤离数据的关卡各占一个教师轮换位置，保留原有各面示范。源文件和原作数据保持同一格式，冻结评估继续由果蝇对全部动作评分。

`manifest.json` 记录通过的局部片段、原作关卡帧、输入时钟和采集截止原因。每段最多用前 16 步热身，并保留至少 16 步用于监督。续训加 `--teacher-windows $teacherManifest` 以混入监督，可重复传入多个清单。启用 `--teacher-every 4` 后，每四次 PPO 更新附带一个教师窗口，按清单中已有的原作关卡轮换。上述 8192 决策的预演按 1／2、3／4、5／6、1／2 面取样。续训复用相同采样进度和阶段顺序。教师窗口用于动作监督，PPO 使用学生自己在原作 Story 执行的动作及奖励。

`scripts/fit_th08_measured_route.py` 在原作采样之外单独更新路线头的最后一层。`--reference-manifest` 保留实际走过的轨迹中网络给 18 个动作的相对分数，`--correction-manifest` 导入同落点实际得到的安全替代动作。脑内活动及其前端保持固定，每份局部窗口的下行神经活动只计算一次。新增更新数单独记录。用相同感知和原作六面自主冻结核验最终走位。

关卡计时停住时，可以把 `--first-stage-frame` 换成 `--first-input-poll`。数值从当前录像关卡进入后的第一处原作输入检查点起算。先到所选输入计数，再等待同一关卡内的可操作状态。输入计数采集遇到面内过场可继续，过场跳过数写入清单。每个训练窗口以真实相邻的原作输入帧和 16 个连续动作作为下限。清单同时保存目标输入计数、实际起止输入计数和关卡帧。
