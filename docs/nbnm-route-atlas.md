# 按关卡进度检索路线

路线库保存原作中实际执行过的干净移动片段。它提供长程参考，不预言所有未来弹幕，也不替学生操作。

## 数据和匹配

- `scripts/build_nbnm_route_atlas.py` 从原作 Story 或 Stage Practice 采集。六面各自采集，避免因为第一面失败而完全看不到后面。
- 只用训练种子。开发、测试种子不可写入路线库；不把评估轨迹拿来训练。
- 采集教师可以在片段以外使用残机、Bomb 推进。但路线片段必须连续无碰撞、无保护、没有 Bomb，且不能跨越阶段变化或采样间隙。因此“教师完成整面”本身不算 NBNM 证据。
- 每条记录包含关卡、攻击阶段、原作阶段时钟、位置、火力、当前 18 个方向的危险特征，以及实际到达的 4、24、96、240 帧落点。最长 240 帧，即正常速度下 4 秒。
- 道中用原作关卡帧；Boss 使用原作阶段计时器。不能把“加载存档以来的时间”冒充阶段进度。
- 查询同时匹配阶段、时间、位置、火力和当前危险特征。不使用当前 RNG 去挑同种子答案。不满足匹配条件时，默认输出零置信度。

可选 `phase_landmarks=true` 提供另一类弱参考：原作阶段、计时和火力相近，但位置或弹幕不匹配时，只使用历史落点作为阶段站位目标。它不复制远处玩家的下一步动作，置信度不超过 0.1，对移动监督的混合权重不超过 5%。两类信息分别标为 `local_continuation`、`phase_landmark`；它们都不是当前路径安全的证明。没有对应阶段记录时，两者都不提供答案。

这是稀疏的路线经验库，不是覆盖整张地图每个位置、每个随机状态的完整危险图。自机狙、击杀时机和玩家位置会改变后续弹幕；历史路线需要实时修正。

## 输入和教师

保留现有 281 维输入的顺序和含义，追加 `18×6=108` 个路线特征，总计 389 维。每个候选动作对应：

1. 与参考下一步落点的一致程度；
2. 向 24 帧落点推进的程度；
3. 向 96 帧落点推进的程度；
4. 向 240 帧落点推进的程度；
5. 当前场景的匹配置信度；
6. 这条记录实际验证过的干净时长。

它们通过独立的人工感觉映射进入原有 VP 端口。完整连接图、脑内神经元、连接方向和 SNN 动力学保持原样。动作和风险仍从 DN 活动读取。

路线先验也参与移动监督，但只在实时 4 帧预测留有余量的候选中形成软偏好。不能用历史路线把危险方向改成安全标签。原有 4/12/24 帧风险监督保持原来的含义；96/240 帧路点不会被当成当前候选动作必然安全的证明。

## 续训

在配置的 `nbnm` 下增加：

```json
"route_prior": {
  "enabled": true,
  "phase_landmarks": true,
  "manifest": "<采集目录>/manifest.json"
}
```

仅在一段 PPO 已全部提交后迁移。新感觉映射零初始化；旧权重、旧 Adam 状态、已采决策数、课程统计和保存的游戏现场继续使用。旧复习数据缺少新增特征时按“无路线先验”处理，不伪造路点。

新输出目录可设置 `resume_checkpoint` 指向原作业的 `latest-training.pt`。启动器优先恢复新目录已有的检查点；首次才使用该来源。不能只读取参数而丢掉 Adam 和原生游戏状态。

`nbnm_route_guidance` 分别记录 `atlas_local_rows`、`atlas_landmark_rows`、`atlas_guided_rows` 和 `atlas_confidence_sum`。采样文件同时保存原作关卡帧、阶段计时、所选路线记录及置信度。必须同时观察匹配覆盖率、首次中弹位置、整面通过率；只增加数据量或者特征维度不能证明路径规划改善。阶段站位提示不能计作已验证路线的覆盖率。

## 开局能力复习

原复习库只有第三、第四面的两张卡，不能据此声称保护了完整开局能力。`evaluate_nbnm_teacher.py --archive-successes --split train` 现在也支持真实开局与整面练习的完整历史。新鲜开局必须明确配置 `full_story_training_seeds`；不会默认采用开发或测试种子。

只有原作确认无 Bomb、无碰撞完成指定任务的历史才可加入。中间截取的短窗口会用此前全部实际动作重新构建当前权重的脑状态；这些数据只用于监督复习，不当作当前策略的 PPO 轨迹。教师失败局仍保留报告，不能包装成成功历史。

## 冷启动恢复修复

原生中断目标 `hp_sub/time_sub` 是可能分别分配的引用地址，不能把它们统一减去一个基址后当作跨进程稳定数值。续训比较改为保留非空引用状态及真实 HP、定时器、位置、速度、几何、脚本事件和游戏 RNG 等状态；兼容旧检查点中“0 代表基址处非空引用、None 代表空引用”的格式。

`scripts/verify_nbnm_saved_worlds.py` 可以直接恢复实际检查点里的游戏现场，验证输入和任务回报相同；重放不产生新的 PPO 数据或参数更新。
